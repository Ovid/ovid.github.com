# Accessibility Audit: Ovid's website (ovid-website)

* **Date:** 2026-10-11 15:43:17
* **Model:** claude-opus-5-5
* **PAAD version:** 2.0.0
* **Commit:** bd2a889ce0cac733b5928257ff559f5633014afd
* **Platform(s):** Web (static HTML)
* **Tech stack:** Perl 5.40, Template Toolkit, Text::Markdown::Blog (custom), Skeleton + normalize CSS, vanilla JS, Prototype.js (starmap), Prism (syntax highlighting), tinysearch (WASM search)
* **Files audited:** 169 generated HTML pages (scanned), about 60 source files read (root/include/*.tt, root/static/css/*.css, root/static/js/*.js, lib/Template/Plugin/Ovid.pm, lib/Text/Markdown/Blog.pm, lib/Ovid/Template/File.pm, lib/Ovid/Site.pm, plus page templates)
* **Existing a11y tooling:** none found
* **Conformance target:** WCAG 2.2 AA (AAA noted as recommendations)
* **Platform guidelines referenced:** N/A (web only)

Audit order: generated HTML first, then traced back to the source in `root/` or `lib/`. Every fix below targets the source, not the generated output.

## Executive Summary

The site has a strong base: `lang` is set, there is a skip link, a labelled main nav, one `h1` per page, alt text on all images, good body-text contrast, underlined prose links, and a global `prefers-reduced-motion` rule. The biggest barrier is the footnote system: on 60 pages the footnote trigger is a `<span>` that keyboard and screen-reader users cannot reach, so they cannot read any footnote. Next come invisible keyboard focus on two buttons on every page, untitled video iframes, looping GIFs, header-less data tables, and an inaccessible starmap. Estimated conformance: **partial AA** (several Level A failures).

## Impact Summary by User Group

- **Screen reader users:** They cannot open footnotes (60 pages). Video iframes have no names, the TOC hierarchy is flat, tag lists lose list semantics, pagination arrows read as punctuation, and the theme toggle does not report its state.
- **Low-vision users:** The "RSS" nav labels, the footnote dialog label and close icon, and the dark-mode "New!" badge fail contrast. Long footnote dialogs clip at 400% zoom.
- **Colorblind users:** On mobile, the current nav item differs from the others only by colour.
- **Motor-impaired users (keyboard/switch/sip-and-puff):** Footnotes and image zoom need a mouse. Two buttons on every page show no focus ring. Back-to-top makes two tab stops. Article tag links are too close together.
- **Cognitive and learning disabilities:** Home and About share a title. The "Talks"/"Public Speaking" names do not match. Search gives no "no results" feedback. Dates show as an ambiguous "MM.DD".
- **Deaf and hard-of-hearing users:** No verified barrier. Caption quality on YouTube could not be checked from the repo (see Audit Metadata).
- **Vestibular and photosensitive users:** Three GIFs loop forever with no pause. The starmap auto-rotates and ignores reduced-motion. No flashing was found.

## Critical Issues (Complete Barriers)

### [C1] Footnote triggers cannot be reached or activated without a mouse
- **File:** `lib/Template/Plugin/Ovid.pm:46` (`add_note`), `root/static/js/Dialog.js:92-98`, `:26`; generated e.g. `articles/a-review-of-openais-new-chatgpt-o1.html:335`
- **Platform:** Web
- **Barrier:** The trigger is `<span aria-label="Open Footnote" class="open-dialog js-only">` with no role, no tabindex and only a `click` listener. With JS on, the `<noscript>` fallback is gone and dialogs are `display:none`. Focus return goes to `<body>` because the span never takes focus.
- **Criterion:** 2.1.1 Keyboard, 4.1.2 Name, Role, Value, 2.4.3 Focus Order — Level A
- **Affects:** Keyboard, switch, voice-control and screen-reader users cannot read any footnote on 60 pages.
- **Fix:** In `Ovid.pm:46` emit `<button type="button" class="open-dialog js-only" id="open-dialog-N" aria-haspopup="dialog" aria-controls="dialog-N"><i class="fa fa-clipboard fa_custom" aria-hidden="true"></i><span class="visually-hidden">Footnote N</span></button>`. Reset Skeleton's button styles for `.open-dialog` in `root/static/css/dialog.css`. Dialog.js then needs no change: native buttons handle Enter and Space, and focus return works.
- **Confidence:** High
- **Found by:** Screen Reader, Keyboard & Motor

## Serious Issues (Major Difficulty)

### [S1] Theme toggle and back-to-top button show no keyboard focus
- **File:** `root/static/css/skeleton.css:199-205` (`button:focus { outline: 0 }`), `root/static/css/main.css:87`, `:207-215`, `:1096-1109`
- **Platform:** Web
- **Barrier:** Skeleton's `button:focus` (specificity 0,1,1) beats main.css's `:focus-visible` (0,1,0). The ID rules also cancel Skeleton's border change, so the focused state looks the same as the unfocused state.
- **Criterion:** 2.4.7 Focus Visible — Level AA
- **Affects:** Sighted keyboard and switch users lose track of focus in the masthead and footer on 167 pages.
- **Fix:** `main.css:87`: `:focus-visible, button:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`. Or delete `outline: 0` at `skeleton.css:205`.
- **Confidence:** High
- **Found by:** Keyboard & Motor, Visual & Color

### [S2] Embedded iframes have no accessible name
- **File:** `lib/Template/Plugin/Ovid.pm:131-133` (`youtube()`), `root/blog/being-a-keynote-speaker.tt2markdown:55` (Google Maps)
- **Platform:** Web
- **Barrier:** None of the 54 iframes on 35 pages has a `title`. Screen readers say "frame" only.
- **Criterion:** 4.1.2 Name, Role, Value — Level A (technique H64)
- **Affects:** Screen-reader users cannot tell which video a frame holds (videos.html has 8 identical unnamed frames).
- **Fix:** `sub youtube ($self, $youtube_id, $title = 'YouTube video')` and emit an HTML-escaped `title="$title"`. Pass real talk titles from callers. Add `title="Map of …"` to the maps iframe.
- **Confidence:** High
- **Found by:** Screen Reader, Multimedia & Temporal

### [S3] Animated GIFs loop forever with no pause control
- **File:** `root/include/image.tt:25`; callers `root/articles/understanding-class-inheritance.tt2markdown:63`, `root/blog/searching-for-extraterrestrial-life-in-our-solar-system.tt2markdown:371`, `root/articles/how-to-defeat-facebook.tt:521`
- **Platform:** Web
- **Barrier:** `opinion.gif` (5.6 s loop), `triton.gif` (about 9 s loop, rotating moon), and `coyote.gif` (1.8 s loop) all have NETSCAPE `loop=0` (infinite). They start automatically next to body text. (`perserverence.gif` stops after about 3 s and passes.)
- **Criterion:** 2.2.2 Pause, Stop, Hide — Level A
- **Affects:** Users with attention disorders (distraction while reading) and vestibular disorders.
- **Fix:** Convert to MP4 and emit `<video muted loop playsinline controls>` from an image.tt branch for `.gif`, or show a still with a link to the animation. Side note: `coyote.gif` exists only in `static/images/`, not in `root/static/images/`.
- **Confidence:** High
- **Found by:** Multimedia & Temporal

### [S4] Starmap is not usable without sight or a mouse
- **File:** `root/starmap.tt:10-22`, `root/static/js/starmap.js:94-95`, `:247-258`, `:330-350`
- **Platform:** Web
- **Barrier:** The canvas has no text alternative. The four checkboxes have bare text and no `<label>`. Star selection works only by mouse click. `#star_id` updates are not announced. Auto-rotation ignores `prefers-reduced-motion`.
- **Criterion:** 1.1.1 (A), 4.1.2 (A), 2.1.1 (A), 4.1.3 (AA); 2.3.3 (AAA)
- **Affects:** Screen-reader, keyboard and voice-control users; vestibular users.
- **Fix:** Wrap each checkbox in `<label>`. Add `role="img" aria-label="Interactive 3-D map of stars near Sol"` to the canvas. Add `role="status"` to `#star_id`. Add a `<select>` of stars that calls the same selection logic. In `starmap.js:94`, skip `rotate_stars` when `matchMedia('(prefers-reduced-motion: reduce)').matches`.
- **Confidence:** High
- **Found by:** Screen Reader, Keyboard & Motor, Multimedia & Temporal

### [S5] Data tables have no header cells
- **File:** `root/publicspeaking.tt:24-27` (uses the non-existent `<theader>`), `root/blog/what-is-socialism.tt:313-315`
- **Platform:** Web
- **Barrier:** Header rows use `<td>`. Screen readers cannot announce column headers for the numeric cells.
- **Criterion:** 1.3.1 Info and Relationships — Level A
- **Affects:** Screen-reader users on 2 pages.
- **Fix:** Use `<thead>` with `<th scope="col">`, and make the first cell of each body row `<th scope="row">`.
- **Confidence:** High
- **Found by:** Screen Reader

## Moderate Issues (Friction)

### [M1] Footnote dialog does not read the note text and is not modal
- **File:** `lib/Template/Plugin/Ovid.pm:53-60`, `root/static/js/Dialog.js:19-37`
- **Platform:** Web
- **Barrier:** `aria-describedby` points at the sr-only "Note number N", not the note. Focus goes to Close. There is no `aria-modal` and the background is not inert.
- **Criterion:** 1.3.1, 4.1.2 — Level A
- **Affects:** Screen-reader users hear "Close footnote, button" but not the note itself.
- **Fix:** Give the note `<div>` an `id`, point `aria-describedby` at it, add `aria-modal="true"`, and drop the "Note number" paragraph.
- **Confidence:** High
- **Found by:** Screen Reader

### [M2] Back-to-top nests a button inside a link
- **File:** `root/include/footer.tt:127`, `root/static/css/main.css:1090-1109`
- **Platform:** Web
- **Barrier:** `<a href="#top"><button>↑</button></a>` is invalid nesting. It gives two tab stops, and the second has no visible focus (S1).
- **Criterion:** 4.1.2, 2.4.3 — Level A
- **Affects:** Keyboard and screen-reader users on 167 pages.
- **Fix:** `<a href="#top" class="arrow" id="scrollToTopButton" aria-label="Back to top">↑</a>`, and move the button styles onto the link.
- **Confidence:** High
- **Found by:** Screen Reader, Keyboard & Motor, Visual & Color

### [M3] Image enlarge overlay is mouse-only
- **File:** `root/include/footer.tt:51-60`, `root/include/image.tt:25`, `root/static/css/image.css:6-8`
- **Platform:** Web
- **Barrier:** The click handler is on a non-focusable `<img>`. The overlay has no role, no name, no focus move and no Escape.
- **Criterion:** 2.1.1 Keyboard — Level A
- **Affects:** Keyboard and switch users cannot view the larger image (57 pages). The inline image is still visible, so this is not a complete barrier.
- **Fix:** Wrap the image in `<a href="[% src %]">` (this works without JS too), or in a `<button aria-label="Enlarge image: …">`. Close on Escape and return focus.
- **Confidence:** High
- **Found by:** Keyboard & Motor, Screen Reader

### [M4] Dark-mode toggle does not expose its state
- **File:** `root/include/dark-mode.tt:1`, `root/static/js/dark-mode.js`
- **Platform:** Web
- **Barrier:** Only the aria-hidden icon changes. There is no `aria-pressed`.
- **Criterion:** 4.1.2 — Level A
- **Affects:** Screen-reader users get no confirmation of the current theme (167 pages).
- **Fix:** `aria-label="Dark mode" aria-pressed="false"`. Set `aria-pressed` in dark-mode.js at init and on click.
- **Confidence:** High
- **Found by:** Screen Reader, Cognitive & Learning

### [M5] Home and About pages have the same title and h1
- **File:** `root/about.tt2markdown:2`
- **Platform:** Web
- **Barrier:** Both are "Ovid Among the Machines".
- **Criterion:** 2.4.2 Page Titled — Level A
- **Affects:** Screen-reader users and users who orient by tab titles or history.
- **Fix:** For example, `title = 'About Curtis “Ovid” Poe';`
- **Confidence:** High
- **Found by:** Screen Reader, Cognitive & Learning

### [M6] Pagination: unlabelled nav, arrow-only links, current page by class only
- **File:** `lib/Ovid/Site.pm:511-537` (`_get_pagination`; nav at :513, prev at :517, active class at :523, next at :530)
- **Platform:** Web
- **Barrier:** Prev/next names are "«" and "»". The current page is marked only by `class="active"`.
- **Criterion:** 2.4.4 Link Purpose, 1.3.1 — Level A
- **Affects:** Screen-reader users on 14 index pages.
- **Fix:** `<nav class="pagination" aria-label="Pagination">`, `aria-label="Previous page"` / `"Next page"`, and `aria-current="page"` on the current link.
- **Confidence:** High
- **Found by:** Screen Reader, Cognitive & Learning

### [M7] Search gives no result-count or "no results" status
- **File:** `root/include/search.tt:34-56`, `:75`; `root/static/css/main.css:172-184`
- **Platform:** Web
- **Barrier:** The `aria-live` `<ul>` is cleared and rebuilt on every keyup. Zero results produce silence. The panel stays open after blur (a possible 2.4.11 issue, not verified in a browser).
- **Criterion:** 4.1.3 Status Messages — Level AA
- **Affects:** Screen-reader and cognitive users cannot tell "no matches" from "broken".
- **Fix:** Add `<p id="search-status" role="status" class="visually-hidden">` and remove `aria-live` from the `<ul>`. Set "N results" or "No results". Use `oninput`. Clear results on Escape and focusout.
- **Confidence:** Medium
- **Found by:** Screen Reader, Cognitive & Learning, Keyboard & Motor

### [M8] Table of contents is a flat list; hierarchy is CSS only
- **File:** `lib/Ovid/Template/File.pm:253`, `:265-274`
- **Platform:** Web
- **Barrier:** Uses `<li class="indent-N">` in one list. The `<nav role="navigation">` has no label and is placed inside a `<p>` (invalid; leaves an empty paragraph).
- **Criterion:** 1.3.1 — Level A
- **Affects:** Screen-reader users on 61 pages (41 have multi-level TOCs).
- **Fix:** Build nested `<ul>`s by level. Use `<nav class="table-of-contents" aria-label="Table of contents">`. Consume the wrapping `<p>` in the `{{TOC}}` substitution.
- **Confidence:** High
- **Found by:** Screen Reader, Cognitive & Learning

### [M9] Tag lists lose list semantics
- **File:** `root/include/tags_for_article.tt:8-9`, `root/include/tag-cloud.tt:3-4`
- **Platform:** Web
- **Barrier:** `role="navigation"` on `<ul>` removes the list role. "Tags:" is a fake list item. The label says "this articles". The footer "Tags" heading is a `<strong>`.
- **Criterion:** 1.3.1 — Level A
- **Affects:** Screen-reader users (about 126 pages for the article list; 167 for the cloud).
- **Fix:** `<nav aria-label="Tags"><ul class="inline">…</ul></nav>`. Move "Tags:" out of the list. Make the cloud heading an `<h2>`.
- **Confidence:** High
- **Found by:** Screen Reader

### [M10] Math timeline lightbox does not contain or return focus
- **File:** `root/blog/is-math-discovered-or-invented.tt2markdown:369-382`
- **Platform:** Web
- **Barrier:** It declares `aria-modal` but Tab leaves the overlay. On close, focus drops to `<body>`.
- **Criterion:** 2.4.3 Focus Order — Level A
- **Affects:** Keyboard users on 1 page.
- **Fix:** Store the opener and restore focus on close. Wrap Tab inside the lightbox, or use a native `<dialog>` with `showModal()`.
- **Confidence:** High
- **Found by:** Keyboard & Motor

### [M11] Article tag links are too close together
- **File:** `root/static/css/main.css:405-415`, `:895-917`
- **Platform:** Web
- **Barrier:** About 20 px tall links on a 21.8 px pitch in the desktop margin column.
- **Criterion:** 2.5.8 Target Size (Minimum) — Level AA
- **Affects:** Users with tremor or limited dexterity (about 126 pages).
- **Fix:** `ul.inline { gap: .3rem }` or `ul.inline a { display:inline-block; min-height:24px }`.
- **Confidence:** Medium
- **Found by:** Keyboard & Motor

### [M12] Footer colophon links crowd when they wrap on phones
- **File:** `root/static/css/main.css:1065-1083`
- **Platform:** Web
- **Barrier:** Vertical pitch is about 19 px when wrapped.
- **Criterion:** 2.5.8 — Level AA
- **Affects:** Touch users with limited dexterity.
- **Fix:** `.colophon-links a { display:inline-block; padding:.3rem 0 }`.
- **Confidence:** Medium (not measured in a browser)
- **Found by:** Keyboard & Motor

### [M13] "RSS" nav labels fail contrast
- **File:** `root/static/css/main.css:303-310`
- **Platform:** Web
- **Barrier:** `--faint` at .58rem: 2.64:1 light, 4.08:1 dark.
- **Criterion:** 1.4.3 Contrast (Minimum) — Level AA
- **Affects:** Low-vision users (167 pages).
- **Fix:** `color: var(--muted)` (5.00:1 / 7.03:1) and font-size ≥ .7rem.
- **Confidence:** High
- **Found by:** Visual & Color

### [M14] Footnote dialog label and close icon fail contrast
- **File:** `root/static/css/dialog.css:35`, `:64`
- **Platform:** Web
- **Barrier:** "Footnote #N" is 2.64:1 light and 4.08:1 dark. The close "×" icon is 2.64:1 in light mode.
- **Criterion:** 1.4.3 / 1.4.11 — Level AA
- **Affects:** Low-vision users (60 pages).
- **Fix:** `color: var(--muted)` at both lines.
- **Confidence:** High
- **Found by:** Visual & Color

### [M15] "New!" badge fails contrast in dark mode
- **File:** `root/static/css/main.css:539-541` (and `root/static/css/dark-mode.css`)
- **Platform:** Web
- **Barrier:** `#B3261E` on `#0F1211` = 2.88:1.
- **Criterion:** 1.4.3 — Level AA
- **Affects:** Low-vision users in dark mode (articles.html, blog.html).
- **Fix:** `[data-theme="dark"] .new { color: #F28B82; }` (7.88:1).
- **Confidence:** High
- **Found by:** Visual & Color

### [M16] Mobile nav marks the current page by colour only
- **File:** `root/static/css/main.css:325-327`
- **Platform:** Web
- **Barrier:** Below 60em the underline bar is hidden. Accent vs muted is about 1.6:1.
- **Criterion:** 1.4.1 Use of Color — Level A
- **Affects:** Colorblind and low-vision users on phones.
- **Fix:** Keep a non-colour cue, e.g. `font-weight:600; text-decoration:underline`.
- **Confidence:** Medium
- **Found by:** Visual & Color

### [M17] Long footnote dialogs clip at high zoom
- **File:** `root/static/css/dialog.css:11-25`
- **Platform:** Web
- **Barrier:** The fixed, centred dialog has no `max-height` or `overflow`.
- **Criterion:** 1.4.10 Reflow — Level AA
- **Affects:** Zoom and magnifier users cannot read long notes or reach Close.
- **Fix:** `max-height: calc(100dvh - 2rem); overflow-y: auto;` and smaller padding below 40em.
- **Confidence:** Medium (not rendered)
- **Found by:** Visual & Color

## Minor Issues & AAA Recommendations

- [AAA] External links open new tabs with no warning; the icon is outside the link and has no `aria-hidden`. `lib/Text/Markdown/Blog.pm:137-139`, `:156-158`; `lib/Template/Plugin/Ovid.pm:34-36`; `root/include/footer.tt:102-103`; `root/include/aatw-logo.tt:1` uses `target="blank"` (typo). Move the icon inside the link with a visually-hidden "(opens in new tab)" — 3.2.5 (G201).
- [AAA] Search input focus is only a 1 px border colour change (`root/static/css/main.css:151-154`, `outline: none`) — 2.4.13.

- Heading skips h1→h3 in `root/articles/constructive-versus-classical-logic-in-perl.tt:64` and `root/articles/what-to-know-before-debating-type-systems.tt2markdown:29` — 1.3.1 best practice.

- Date shows as "2019 / 11.01" (`root/include/header.tt:203-204`) — screen readers say "eleven point zero one". Add a visually-hidden full date — advisory.
- "min read" with no number when JS is off (`root/include/header.tt:208`) — advisory.
- Prism tokens `tag`/`property`/`deleted` (dark, 2.08:1) and `attr-name` (light, 3.22:1) are not overridden (`root/static/css/prism.css:86-102`, `root/static/css/dark-mode.css`) — 1.4.3; affects about 3 non-Perl code blocks.
- Google Maps iframe is fixed at `width="640"` and causes horizontal scrolling at 320 px (`root/blog/being-a-keynote-speaker.tt2markdown:55`) — 1.4.10.
- Dark-mode code `::selection` background `#b3d4fc` gives 1.27:1 (`root/static/css/prism.css:33-43`) — best practice.
- `@media (prefers-contrast: high)` is invalid and never matches; use `more` (`root/static/css/collapsible.css:158`). No `forced-colors` handling anywhere — best practice.
